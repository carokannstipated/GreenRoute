# GreenRoute — Codebase Architecture Report

## Overview

GreenRoute is an iOS application that encourages users to take outdoor breaks and conduct walking meetings in nearby green areas. It detects periods of physical inactivity, suggests the closest green space within a user-defined walking range, and provides turn-by-turn walking routes. The project follows a layered architecture with strict separation between domain logic, data persistence, platform services, and the UI.

The codebase is split into one Xcode application target and three local Swift packages:

| Layer | Module | Responsibility |
|---|---|---|
| Domain | `GreenRouteDomain` | Pure business logic, models, protocols |
| Data | `GreenRouteData` | SwiftData persistence, UserDefaults settings |
| Service | `GreenRouteService` | CoreMotion, CoreLocation, MapKit, notifications |
| App | `GreenRoute` | SwiftUI views, ViewModels, composition root |

---

## GreenRouteDomain

Contains all business rules, domain models, and protocols. Has zero platform dependencies — it imports only `Foundation`.

**`Package.swift`** — declares the `GreenRouteDomain` library target with `platforms: [.iOS(.v26)]`. No external dependencies.

**`GreenRouteDomain.swift`** — empty file generated by the SPM template. Serves as the module namespace entry point with no active declarations.

### Models

#### `Models/ValueObjects/Coordinate.swift`
A `Sendable`, `Codable` value type representing a geographic point (latitude/longitude). Enforces valid ranges via `precondition`. Includes a `distance(to:)` method implementing the Haversine formula to compute the great-circle distance in metres between two coordinates.

#### `Models/ValueObjects/DistanceMeters.swift`
A thin `Sendable` value type wrapping a `Double` distance in metres. Conforms to `Comparable` so distances can be directly compared with `<`, `<=`, etc. Enforces non-negative values via `precondition`. Used throughout the domain to keep distance semantics explicit and prevent raw-Double confusion.

#### `Models/ValueObjects/SavedAddress.swift`
A `Codable`, `Sendable` value type representing a user-saved address with a display name and a `Coordinate`. Used to persist home and work addresses in settings.

#### `Models/GreenArea.swift`
Represents a green space POI. Contains an `id`, `name`, `Coordinate`, and a `Kind` enum (`park`, `forest`, `natureReserve`, `beach`, `other`). Conforms to `Identifiable`, `Hashable`, and `Sendable`. Enforces non-empty id and name via `precondition`.

#### `Models/Recommendation.swift`
Represents a generated green-break suggestion. Contains the target `GreenArea`, the distance at creation time, estimated walk minutes, a `Trigger` (`.inactivity`, `.pattern`, `.userRequested`), and a creation timestamp. Conforms to `Identifiable`, `Hashable`, and `Sendable`.

#### `Models/InactivityEvent.swift`
Represents a detected period of physical stillness with a `start` and `end` date. Provides a `duration` computed property in seconds. `end` must not be earlier than `start` (enforced by `precondition`).

#### `Models/LocationVisit.swift`
Records a visit to a physical location with an arrival time, optional departure, the `Coordinate`, and an inferred `PlaceCategory` (home, work, other). Used for pattern detection.

#### `Models/RecurringPattern.swift`
Captures a detected behavioural pattern (e.g. regular sedentary periods at specific times or places). Used by the pattern detection pipeline.

#### `Models/RecommendationDecision.swift`
Records what a user did with a recommendation (accepted or dismissed), linking back to the recommendation by id. Enables future analytics.

#### `Models/AppSettings.swift`
A `Codable`, `Sendable` struct holding all user preferences: `maxRouteDurationMinutes` (Int), `homeAddress` (optional `SavedAddress`), `workAddress` (optional `SavedAddress`). Provides an `AppSettings.default` static instance with sensible defaults.

---

### Protocols

#### `Protocols/Repositories.swift`
Defines all repository contracts used by the domain layer. Each protocol is `Sendable` so implementations can live in actors or be passed across concurrency boundaries:

- `InactivityEventRepository` — save and fetch `InactivityEvent` by date range
- `LocationVisitRepository` — save and fetch `LocationVisit` by date range
- `RecommendationRepository` — save and fetch `Recommendation` by date range
- `RecommendationDecisionRepository` — save and fetch `RecommendationDecision` by recommendation id
- `RecurringPatternRepository` — save and fetch the latest `RecurringPattern`
- `GreenAreaRepository` — save and fetch all cached `GreenArea` values
- `SettingsRepository` — synchronous `load() -> AppSettings` and `save(_ settings:)`

#### `Protocols/Providers.swift`
Defines platform-facing service abstractions:

- `GreenAreaProvider` — fetch nearby green areas given a `Coordinate` and search radius
- `RouteProvider` — compute a walking `RouteResult` (polyline + travel time) between two coordinates
- `NotificationScheduler` — schedule a `NotificationRequest` via the system notification centre
- `RouteResult` — value type returned by `RouteProvider` containing an array of `Coordinate` points and expected travel time in seconds

#### `Protocols/TimeProviding.swift`
A `Clock` abstraction used throughout the service layer to make time-dependent logic testable by injection.

---

### Engines

#### `Engines/RecommendationEngine.swift`
Pure, stateless rule engine. Given an `InactivityEvent`, the user's current location, a list of nearby `GreenArea` values, a threshold, and a `maxDistance`, it returns a `Recommendation` or `nil`. Rules: inactivity duration must meet the threshold, and the nearest green area must be within `maxDistance`. Estimates walk time at 1.4 m/s. All logic is deterministic and has no side effects, making it fully unit-testable.

#### `Engines/NotificationPolicy.swift`
Stateless policy guard. Determines whether a notification may be sent given the count sent today, the timestamp of the last notification, and the current time. Configurable with `maxPerDay` and `minimumInterval` (cooldown). Prevents notification spam.

#### `Engines/PatternDetector.swift`
Stateless engine that analyses a sequence of `InactivityEvent` records to detect daily recurring time windows. It extracts the minutes-from-midnight of each episode's start, computes the average, and counts how many fall within a configurable tolerance (default ±30 minutes). If enough episodes match (default minimum 3), it returns a `RecurringPattern` with a `TimeWindow` and a confidence ratio. Used to enable proactive recommendations based on learned habits rather than reactive inactivity alone.

---

### Use Cases

#### `UseCases/GenerateGreenBreakUseCase.swift`
The central orchestration use case for the green-break feature. Executes sequentially:
1. Fetches nearby green areas from `GreenAreaProvider`
2. Passes them to `RecommendationEngine` for rule evaluation
3. Persists the recommendation via `RecommendationRepository`
4. Optionally schedules a push notification, guarded by `NotificationPolicy`

Returns an `Output` value containing the recommendation (if any) and whether a notification was scheduled. Fully injectable for testing.

#### `UseCases/RecordInactivityUseCase.swift`
Persists an `InactivityEvent` to the repository. Called whenever the service layer detects a period of stillness.

#### `UseCases/DetectRecurringPatternUseCase.swift`
Analyses recent `LocationVisit` records via `PatternDetector` and persists any detected pattern to `RecurringPatternRepository`.

## GreenRouteData

Provides concrete implementations of the domain's repository protocols using SwiftData for structured persistence and `UserDefaults` for settings.

**`Package.swift`** — declares the `GreenRouteData` library with a dependency on `GreenRouteDomain`. Platforms set to iOS 26.

**`GreenRouteData.swift`** — empty SPM template file. No active declarations.

#### `SwiftDataStack/Schema.swift`
Defines the full SwiftData schema by listing all `@Model` entity types that should be registered with the persistent container.

#### `SwiftDataStack/ModelContainerFactory.swift`
Factory function `makePersistentContainer()` that creates and configures the `ModelContainer` with the full schema. Called once at app startup in `AppCompositionRoot`.

Each entity is a SwiftData `@Model` class that mirrors a domain model for persistence. They are intentionally kept separate from domain models to allow the persistence layer to evolve independently.

- `InactivityEventEntity` — persists `InactivityEvent`

- `RecommendationDecisionEntity` — persists `RecommendationDecision`

- `GreenAreaEntity` — persists `GreenArea`

- `RecommendationMapper`
- `RecommendationDecisionMapper`
- `LocationVisitMapper`
- `GreenAreaMapper`
- `RecurringPatternMapper`

#### `Repositories/SwiftDataInactivityEventRepository.swift`
`InactivityEventRepository` implementation backed by SwiftData. Saves and fetches `InactivityEvent` records within a date range using a `ModelContainer`.

#### `Repositories/SwiftDataRecommendationRepository.swift`
`RecommendationRepository` implementation backed by SwiftData. Saves and fetches `Recommendation` records by date range.

#### `Repositories/SwiftDataRecommendationDecisionRepository.swift`

#### `Repositories/SwiftDataLocationVisitRepository.swift`
`LocationVisitRepository` implementation backed by SwiftData.

#### `Repositories/SwiftDataGreenAreaRepository.swift`
`GreenAreaRepository` implementation backed by SwiftData.

#### `Repositories/SwiftDataRecurringPatternRepository.swift`
`RecurringPatternRepository` implementation backed by SwiftData.

#### `Repositories/UserDefaultsSettingsRepository.swift`
`SettingsRepository` implementation backed by `UserDefaults`. Stores `maxRouteDurationMinutes` as a plain integer and serialises `homeAddress`/`workAddress` as JSON using `JSONEncoder`/`JSONDecoder`. ## GreenRouteService

Bridges the domain to iOS platform APIs. All types in this module are either `actor`s or `Sendable` structs to safely cross Swift concurrency boundaries.

**`Package.swift`** — declares the `GreenRouteService` library with dependencies on `GreenRouteDomain` and system frameworks (CoreMotion, CoreLocation, MapKit, UserNotifications). Platforms set to iOS 26.

### Public API

#### `Public/GreenRouteServiceFacade.swift`
The public `GreenRouteService` protocol and its production implementation `GreenRouteServiceFacade`. The protocol exposes:
- `events: AsyncStream<ServiceEvent>` — a continuous stream of domain events
- `greenAreaProvider`, `notificationScheduler`, `routeProvider` — injectable service handles
- `start()` / `stop()` — lifecycle control

`GreenRouteServiceFacade` holds a `DependencyContainer` and routes emitted events into the `AsyncStream` via a continuation.

#### `Public/GreenRouteServiceFactory.swift`
Static factory `GreenRouteServiceFactory.make()` that wires production dependencies and returns a ready `GreenRouteService` instance. The single call site in `AppCompositionRoot` keeps composition explicit.

#### `Public/ServiceEvent.swift`
The sealed event type emitted by the service layer:
- `.inactivityDetected(InactivityEvent)` — user has been stationary beyond the threshold
- `.significantLocationChange(latitude:longitude:)` — user has moved significantly
- `.locationVisit(LocationVisit)` — a location visit has been classified

---

### Integrations — Location

#### `Integrations/Location/LocationClient.swift`
Protocol abstracting CoreLocation. Defines `requestWhenInUsePermission()`, `startMonitoringSignificantLocationChanges(_:)`, `stopMonitoringSignificantLocationChanges()`, and `requestLocation()`. Enables the location monitor to be tested without a real device.

#### `Integrations/Location/CoreLocationClient.swift`
Production `CLLocationManager`-backed implementation of `LocationClient`. Bridges CoreLocation delegate callbacks into the closure-based `LocationClient` API.

#### `Integrations/Location/LocationMonitor.swift`
An `actor` that manages the location lifecycle. On `start()`, it requests permission, begins monitoring for significant location changes, and fires a one-time `requestLocation()` to obtain an immediate fix. Each location update is classified by time of day into a `PlaceCategory` and emitted as both a `.significantLocationChange` and a `.locationVisit` event.

---

### Integrations — Motion

#### `Integrations/Motion/MotionClient.swift`
Protocol abstracting `CMMotionActivityManager`. Defines `startActivityUpdates(_:)` and `stopActivityUpdates()`. Provides a `MotionActivity` value type with `isMoving` and `isStationary` booleans.

#### `Integrations/Motion/CoreMotionMotionClient.swift`
Production `CMMotionActivityManager`-backed implementation of `MotionClient`.

#### `Integrations/Motion/InactivityMonitor.swift`
An `actor` implementing a state machine with three states: `.active`, `.maybeInactive(since:)`, and `.inactive(since:)`. On each motion update it transitions states and emits `.inactivityDetected` when the user has been stationary for longer than the configured threshold (default 20 minutes). Once inactive, it stays quiet until motion resumes.

---

### Integrations — Green Area Search

#### `Integrations/GreenArea/LocalSearching.swift`
Internal protocol abstracting MapKit local search, plus the `LocalSearchResult` plain value type (`name`, `latitude`, `longitude`, `pointOfInterestCategory`). Keeps `MKPointOfInterestCategory` contained in the service layer — the domain never sees it.

#### `Integrations/GreenArea/MKLocalSearcher.swift`
Production `LocalSearching` implementation. Builds a single `MKLocalSearch.Request` filtered to `.park`, `.beach`, and `.nationalPark` categories within a bounding region derived from the search radius. Returns the matched map items as `[LocalSearchResult]`.

#### `Integrations/GreenArea/MapKitAreaProvider.swift`
`GreenAreaProvider` implementation. Delegates to `LocalSearching` and maps raw search results to `GreenArea` domain values, translating `MKPointOfInterestCategory` to `GreenArea.Kind`.

---

### Integrations — Routing

#### `Integrations/Routing/MKRouteProvider.swift`
`RouteProvider` implementation backed by `MKDirections`. Requests a walking route between two coordinates and extracts the polyline coordinates from the first returned route. Exposes a private `MKPolyline` extension to convert the polyline into an array of `CLLocationCoordinate2D`.

---

### Integrations — Notifications

#### `Integrations/Notification/NotificationCenterScheduling.swift`
Protocol abstracting `UNUserNotificationCenter` to enable fake implementations in tests.

#### `Integrations/Notification/UserNotificationScheduler.swift`
`NotificationScheduler` implementation. Converts a domain `NotificationRequest` into a `UNNotificationRequest` and schedules it via `UNUserNotificationCenter` with a 1-second trigger.

---

### Utils

#### `Utils/Clock.swift`
`Clock` protocol with a single `now() -> Date` requirement and a `SystemClock` production implementation. Injected into monitors so tests can control the passage of time deterministically.

---

### Composition

#### `Composition/DependencyContainer.swift`
An internal `actor` that owns and wires the `InactivityMonitor` and `LocationMonitor`. Provides `start()` and `stop()` to coordinate their lifecycles, and routes events from both monitors through a shared `EventSink` closure to the `GreenRouteServiceFacade` stream.

## GreenRoute (App Target)

The SwiftUI application. ViewModels follow the `@MainActor @Observable final class` pattern with `@State private var viewModel` in views and custom `init` for dependency injection. No logic lives in views.

### Xcode Template Leftovers

#### `ContentView.swift`
The default SwiftUI view generated by the Xcode project template. Not used anywhere in the running app — `AppCompositionRoot` is the actual root. Kept in the target but has no functional role.

#### `Item.swift`
A SwiftData `@Model` class generated by the Xcode template with a single `timestamp: Date` property. Not used in the app. Can be safely deleted once the template scaffolding is cleaned up.

---

### App Entry Point

#### `App/GreenRouteApp.swift`
The `@main` `App` entry point. Holds the `UIApplicationDelegate` for push notification registration and presents `AppCompositionRoot` as the root view.

#### `Composition/AppCompositionRoot.swift`
The single composition root for the app. Creates all dependencies — `ModelContainer`, repositories, service, use cases, and a shared `UserDefaultsSettingsRepository` instance — then constructs all ViewModels and injects them into the tab view. Shows a `ProgressView` while bootstrapping and a `ContentUnavailableView` if setup fails. The shared settings repository ensures `SettingsViewModel` and `GreenBreakViewModel` always read from and write to the same store.

---

### Preview Entry Point

#### `Features/Preview.swift`
A top-level `#Preview` block that renders `AppCompositionRoot` directly. Provides a full-app preview in Xcode's canvas without needing to stub individual ViewModels. Also used as the `#Preview` target in `RecommendationCard.swift`.

---

### Shared

#### `Shared/LocationStore.swift`
An `@Observable` class that acts as the single in-memory holder of the user's last known coordinate. Written to by `GreenBreakViewModel` when a `.significantLocationChange` event arrives. Both `GreenBreakViewModel` and `GreenMeetingViewModel` hold a reference to the same instance, ensuring consistent location state across features.

### GreenBreak Feature

#### `Features/GreenBreak/GreenBreakViewModel.swift`
`@MainActor @Observable` ViewModel for the GreenBreak tab. Responsibilities:
- Starts and stops the `GreenRouteService` and listens to its `AsyncStream`
- Handles `.inactivityDetected` events by calling `GenerateGreenBreakUseCase`
- Exposes `generateOnDemand()` for user-initiated generation
- Reads `maxRouteDurationMinutes` from `SettingsRepository` on each generate call (via computed `maxDistance`) so the distance cap always reflects the current setting
- Holds `maxRouteDurationMinutes` as a stored property for stepper binding, kept in sync via `reloadSettings()` (called on view appear) and `setMaxRouteDuration(_:)` (called on stepper interaction)
- Manages session state: `recommendation`, `isShowingMap`, `isWalking`, `noResultsNearby`
- `acceptRecommendation()`, `resumeSession()`, `endSession()`, `dismissRecommendation()` handle the full session lifecycle

#### `Features/GreenBreak/GreenBreakView.swift`
Root view for the GreenBreak tab. Renders one of four states:
1. **Idle** — leaf icon, tagline, and "Generate Green Route" button
2. **Recommendation card** — shown when a suggestion is available and the walk hasn't started
3. **No results** — shown when `noResultsNearby` is true; includes a `maxRouteDurationMinutes` stepper and a "Try again" button
4. **Session pill** — a floating glass pill at the top of the screen when `isWalking && !isShowingMap`, letting the user resume the map or end the session

Presents `RouteMapView` as a sheet. Keeps `isWalking` bound bidirectionally into the map sheet so walk state survives the sheet being swiped down.

#### `Features/GreenBreak/RecommendationCard.swift`
Standalone card view for a single `Recommendation`. Shows the destination name, distance, estimated walk time, and accept/dismiss buttons. Supports swipe-to-dismiss with a `DragGesture` — dragging more than 120 pts in either direction triggers `onDismiss`.

#### `Features/GreenBreak/RouteMap/RouteMapViewModel.swift`
`@MainActor @Observable` ViewModel for the walking route map. Loads the walking route from the user's current location to the recommended green area via `RouteProvider`. Exposes `outboundResult`, `isLoadingRoute`, and `routeError`.

#### `Features/GreenBreak/RouteMap/RouteMapView.swift`
Map sheet view for a green-break route. Shows a `Map` with a `UserAnnotation`, a `Marker` for the destination, and a `MapPolyline` for the calculated route. Animates the camera to fit the full route on load. Includes a bottom card with destination info and a Start/Stop walk button. `isNavigating` is a `@Binding` passed in from `GreenBreakViewModel` so walk state persists if the sheet is dismissed and reopened.

---

### GreenMeeting Feature

#### `Features/GreenMeeting/GreenMeetingViewModel.swift`
`@MainActor @Observable` ViewModel for the GreenMeeting tab. The user inputs a total meeting duration; the VM calculates the maximum outbound walking distance (half the total time at 1.4 m/s, capped at 2 km), fetches green areas within that radius, and selects the one closest to the ideal halfway point. Manages `isSearching`, `isWalking`, `isShowingMap`, `foundGreenArea`, and `errorMessage`.

#### `Features/GreenMeeting/GreenMeetingView.swift`
Root view for the GreenMeeting tab. Shows a two-wheel `Picker` (hours and minutes) and a "Start Green Meeting" button. While searching, the button shows a `ProgressView`. When a session is active and the map is dismissed, shows the same session pill pattern as `GreenBreakView`.

#### `Features/GreenMeeting/MeetingMap/GreenMeetingMapViewModel.swift`
`@MainActor @Observable` ViewModel for the circular meeting route map. Fetches both legs of the route concurrently using `async let` — outbound (origin → green area) and return (green area → origin). Exposes `outboundResult`, `returnResult`, `combinedTravelTimeMinutes`, and loading/error state.

#### `Features/GreenMeeting/MeetingMap/GreenMeetingMapView.swift`
Map sheet view for a green-meeting route. Shows both the outbound polyline (solid green) and the return polyline (semi-transparent green) on the map. Animates camera to fit both legs combined. Bottom card shows the green area name, combined travel time, and a Start/Stop walk button. `isNavigating` is a `@Binding` from `GreenMeetingViewModel`.

---

### Settings Feature

#### `Features/Settings/SettingsViewModel.swift`
`@MainActor @Observable` ViewModel for the Settings tab. Holds `maxRouteDuration`, `homeAddress`, and `workAddress` as stored properties loaded from `SettingsRepository` on init. Each setter updates both the in-memory copy and persists to the repository. Exposes `reload()` so `RoutePreferencesView` can refresh state on appear (keeping it in sync with changes made via `GreenBreakView`).

#### `Features/Settings/SettingsView.swift`
Settings tab root view rendered as a `Form` with navigation links to sub-pages. Contains four private sub-views:

- **`PermissionsView`** — shows location and notification permission status with buttons to open the device Settings app
- **`RoutePreferencesView`** — shows the max duration stepper, home address picker, and work address picker. Calls `viewModel.reload()` on appear to pick up any changes made elsewhere
- **`AddressPickerView`** — a full-page address search backed by `AddressSearchViewModel`. Uses `.searchable(placement: .navigationBarDrawer(displayMode: .always))` for a persistent search bar. Shows a floating glass "Remove Address" button that hides when the keyboard is visible (tracked via `NotificationCenter` keyboard notifications)
- **`AboutView`** — shows the app version from `CFBundleShortVersionString`

Includes a private `settingsIcon(systemName:color:)` `View` extension for the coloured icon badges used in list rows.

#### `Features/Settings/PermissionsViewModel.swift`
`@MainActor @Observable` ViewModel for the permissions page. Reads `CLLocationManager.authorizationStatus` and queries `UNUserNotificationCenter` for current notification settings. Exposes human-readable status strings and `openSettings()` which deep-links to the app's system settings page via `UIApplication.openSettingsURLString`.

#### `Features/Settings/AddressSearchViewModel.swift`
`@MainActor @Observable` ViewModel subclassing `NSObject` to implement `MKLocalSearchCompleterDelegate`. Holds an `MKLocalSearchCompleter` and exposes `results: [MKLocalSearchCompletion]` updated as the user types. `resolve(_:)` takes a selected completion, performs a full `MKLocalSearch` to geocode it, and returns a `SavedAddress` with display name and coordinate.

## Dependency Graph

```
GreenRoute (App)
    ├── GreenRouteDomain
    ├── GreenRouteData
    │       └── GreenRouteDomain
    └── GreenRouteService
            └── GreenRouteDomain
```

`GreenRouteDomain` has no dependencies. `GreenRouteData` and `GreenRouteService` each depend only on `GreenRouteDomain`. The app target depends on all three. This means domain logic can always be tested in isolation and platform code can be swapped without touching business rules.
